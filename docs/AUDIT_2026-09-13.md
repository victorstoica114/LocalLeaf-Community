# Audit LocalLeaf Community — candidat 0.2.13

Auditul acoperă motorul de sincronizare, transportul HTTP/Socket.IO, autentificarea, setările, interfața VS Code, colaboratorii, utilitarele, testele, buildul și site-ul de prezentare. Modificările de sincronizare din candidatul 0.2.12 sunt păstrate. Această verificare adaugă corecții și curățenie peste ele.

## Eliminarea reconectărilor periodice

Problema raportată nu provenea dintr-un timer de cinci minute. Codul verifica transportul la 30 de secunde și reconcilia proiectul la două minute. Pe serverul query-protocol, refresh-ul proiectului înlocuia conexiunea principală; logul instalației 0.2.12 confirma reconectări repetate ale unei sesiuni active. Termenul de cinci minute din autentificarea prin browser este separat.

În 0.2.13:

- Evenimentele Overleaf și watcher-ele locale mențin sincronizarea curentă.
- Heartbeat-ul nativ Socket.IO detectează pierderea conexiunii. Recuperarea începe la deconectare sau la o operație care constată pierderea transportului, cu întârzieri progresive până la 30 de secunde. Se oprește la recuperare, expirarea autentificării sau închiderea sesiunii.
- O eroare de fișier pe o conexiune sănătoasă nu pornește un ciclu de reconectare.
- Revenirea în fereastra VS Code după minimum 30 de secunde de absență recuperează schimbările ratate, cel mult o dată pe minut. `Sync Now` permite verificarea explicită.
- Snapshotul query-protocol folosește o conexiune temporară și păstrează conexiunea principală, identitatea ei și abonamentele la documente. Cererile simultane pentru același snapshot sunt reunite; conexiunea temporară este închisă și la eroare sau anulare.
- Protocolul care s-a conectat cu succes este reutilizat după o întrerupere. Prima conectare păstrează fallback-ul legacy → query.
- Notificarea de autentificare expirată este deduplicată pe server până la reautentificare. Erorile tranzitorii de pornire sunt prezentate în status și log.
- Dialogurile închise sau ignorate pentru aceleași fișiere locale nu reapar la verificările din fundal ale sesiunii. Căile sau conținutul schimbat și `Sync Now` permit review din nou. Dismiss nu șterge strămoșul unui fișier eliminat pe server; un upload eșuat rămâne vizibil ca eroare de fișier, fără reconectarea transportului sănătos.

Nu există un timer care reîncearcă sincronizarea unei sesiuni sănătoase. Dacă serverul omite complet un eveniment fără să întrerupă conexiunea, recuperarea are loc la revenirea în fereastră sau la `Sync Now`; eliminarea pollingului presupune acest compromis.

## Alte corecții

| Domeniu | Problemă și corecție |
|---|---|
| Protejarea copiilor locale | Un eveniment remote fără strămoș cunoscut nu mai suprascrie o copie locală salvată și diferită. |
| Concurența snapshoturilor | Snapshoturile secundare nu mai invalidează evenimentele conexiunii principale. Căutările din operațiile pe fișiere modifică numai calea protejată și păstrează arborele la eșec. Regresiile acoperă evenimente primite în timpul refresh-ului și handler-e deja active. |
| Identitatea după așteptare | Handler-ele remote rezolvă din nou ID-ul și calea după obținerea lock-ului. Reproducerea în care documentul X era mutat, iar documentul Y ocupa vechea cale nu mai permite aplicarea editării lui X peste Y. |
| Structura inclusă deja în snapshot | Rename/move duplicat păstrează strămoșul; snapshoturile complete reconciliază calea locală înainte de calculul candidaților pentru cleanup. Metadatele ștergerilor deja incluse sunt păstrate într-un cache limitat, iar o cale reutilizată de alt ID nu este ștearsă. |
| Înlocuirea atașamentelor | Eșecul înlocuirii, inclusiv al restaurării copiei de rezervă, păstrează hashul anterior și jurnalul recuperabil. |
| Persistență | Încărcarea validează întregul set înainte de publicare; versiunile negative sunt respinse. Erorile de scriere/sincronizare elimină fișierul temporar. |
| Setări | Operațiile sunt serializate, scrierile sunt atomice, iar o scriere eșuată nu blochează operațiile următoare. Schimbarea serverului/proiectului închide sincron sesiunea veche înainte de publicarea noii ținte. Actualizarea datei ultimei sincronizări nu schimbă workspace-ul activ. |
| UI asincron | Rezultatele vechi de inițializare, proiecte, refresh și autentificare sunt ignorate după schimbarea sesiunii. O invalidare în timpul construirii panoului provoacă reconstruirea lui. |
| Colaboratori | Căile sunt citite din arborele activ; decorațiile vechi sau invalide și utilizatorii rămași după reconectare sunt eliminați. |
| HTTP | Un request nu mai pornește după dispose dacă importul asincron era încă în curs. Descărcările pe intervale validează totalul și revizia înainte de concatenare. |
| Autentificare | Redirecturile de login sunt validate față de server și calea lui. Anularea în timpul upgrade-ului WebSocket nu mai lasă o eroare de socket netratată. |
| Build | Worker-ul de merge era emis într-un subdirector diferit de cel așteptat la runtime; un fișier vechi masca problema. Intrările numite produc acum cele două bundle-uri la căile corecte. |
| Teste | Un fixture UI putea rămâne cu un Promise nerezolvat, iar Node ieșea cu succes înainte de restul verificărilor. Fixture-ul este corectat; runner-ele detectează acum testele rămase incomplete. |
| Utilitare | Un bloc LaTeX foarte mare și neterminat nu mai folosește spread pe sute de mii de linii. Erorile de acces la directoare nu mai sunt confundate cu absența lor. |

## Curățenie și optimizări

- Eliminate metode API și helpers fără apelanți, vechiul scheduler de health/reconciliere, metode nefolosite de credentials/settings, constante nefolosite și cache-ul duplicat pentru căile colaboratorilor.
- Eliminat runner-ul vechi care crea proiecte; fixture-ul folosit de integrarea locală este păstrat separat. Testul serverului folosește proiectul ales explicit și autentificarea normală a extensiei.
- Calculat o singură dată hashul unui conținut sincronizat; evitate scrierile și fsync-urile pentru înregistrări identice. Merge-ul păstrează BOM-ul UTF-8.
- Eliminat `@types/minimatch`, deoarece versiunea instalată include tipuri proprii.
- Eliminate CSS nefolosit, variabile CSS nefolosite și importul CSS duplicat din site. Actualizate `@humanfs/node` și `js-yaml` pentru vulnerabilitățile raportate de auditul npm.
- Șterse 26 de directoare generate vechi sau rămase după diagnostice, cu validarea căilor înaintea ștergerii, inclusiv `out` și `dist`; buildul a fost refăcut din surse. Testele locale își închid motoarele și își elimină propriile directoare temporare.
